**Microsoft SQL Server** - СУБД с клиент-серверной архитектурой: клиент отправляет запросы на T-SQL, а сервер их обрабатывает и выполняет.

> ⚠️ **База данных** состоит из файлов данных (`.mdf`) и файла журнала транзакций (`.ldf`). Основная работа с сервером ведется через среду **SQL Server Management Studio (SSMS)**.

</p>

> 💡 **Серверы являются экземплярами (*Instances*)!** Это конкретная реализация шаблона (например, класса или структуры).

Для подключения к **SQL Server Management Studio** вводятся имя сервера и параметры авторизации.

> 🏨 **Аналогия структуры:**
> * **Компьютер** - это отель.
> * **Серверы** - это этажи (экземпляры).
> * **Базы данных (БД)** - это отдельные номера.

#### 🛠 Окно в SQL Server Management Studio делится на:
* **Оконное меню** - набор команд для управления сервером.
* **Панель инструментов** - кнопки быстрых действий и операций.
* **Панель «Object Explorer»** - обозреватель объектов сервера и баз данных.
* **Рабочая область** - основная зона выполнения запросов и работы с объектами.

</p>

#### 📊 Типы данных:

1. **Числовые**:
   * **Целые**: `TINYINT`, `SMALLINT`, `INT`, `BIGINT`
   * **Дробные**: `DECIMAL`, `REAL`, `FLOAT`

2. **Строковые**:
   * **ASCII**: `CHAR`, `VARCHAR`
   * **Unicode**: `NCHAR`, `NVARCHAR`  
   *(Длина строки указывается в скобках, например `VARCHAR(50)`)*

3. **Специальные**:
   * `BIT` - логический тип (`0` / `1`)
   * `DATETIME` - дата и время
   * `MONEY` - денежный формат

---

📌 **Файлы БД:** Файлы базы данных имеют расширения `.mdf` (основной файл данных) и `.ldf` (журнал транзакций).

📌 **Метаданные** - это системная информация о действиях пользователей и о том, кем именно было совершено каждое действие.

В ветке **`Database` ➔ `System Databases`** хранятся системные БД:
* `master`
* `model`
* `msdb`
* `tempdb`

---

#### 🔑 Настройка ключей и таблиц:
Базы данных и таблицы можно создавать в GUI. Ввод и редактирование данных доступны через контекстное меню: **«Изменить первые 200 строк»** (*Edit Top 200 Rows*).

> ⚠️ **Автоинкремент первичного ключа:**  
> Если первичному ключу (`Primary Key`) требуется автоматическое заполнение последовательными числами, для него включается **«Спецификация идентификатора»** (*Identity Specification*), где задаются:
> * **Начальное значение** (*Identity Seed*)
> * **Шаг приращения** (*Identity Increment*)

**SQL Server Management Studio (SSMS)** - графический инструмент администрирования для формирования структуры БД, выполнения T-SQL запросов и управления сервером.

Установили **SQL Server 2025** и подключились к ядру СУБД через SSMS. Создали базу данных через запрос `CREATE DATABASE`.

* **Хранимые процедуры** - выполняют запросы и бизнес-логику на стороне сервера.

#### ⚙️ Системные базы данных:
* **`master`** - хранит системные настройки, учетные записи, роли и сведения обо всех БД на сервере.

* **`msdb`** - содержит информацию о резервном копировании, оповещениях и задачах планировщика (SQL Server Agent).
* **`tempdb`** - хранилище временных объектов и промежуточных результатов. **Полностью пересоздается при каждом перезапуске сервера!**

#### 💻 Управление БД через T-SQL:

* **Создание БД:**
  ```sql
  CREATE DATABASE название_бд;
  ```

* **Удаление БД:**
  ```sql
  DROP DATABASE название_бд;
  ```

* **Прикрепление существующего файла базы (`.mdf`):**
  ```sql
  CREATE DATABASE название_бд
  ON PRIMARY (FILENAME = 'путь_к_файлу.mdf')
  FOR ATTACH;
  ```

> ⚡ **Запуск выполнения скрипта:**
> Нажатие клавиши <kbd>F5</kbd> или кнопки **«Execute»**.

* **Базовый запрос для выборки всех записей:**
  ```sql
  SELECT * FROM название_таблицы;
  ```

## Возможности СУБД

- пользовательские интерфейсы;
- физическая независимость данных (менять типы файлов, но не программы сами);
- логическая независимость данных (добавлять таблицы и поля, без переписывания программы самой);
- оптимизация запросов;
- целостность данных;
- управление параллелизмом (когда много пользователей к одним и тем же данным доступ имеют);
- резервное копирование и восстановление;
- безопасность баз данных.

**Аутентификация** – проверка подлинности учётки пользователя.

**Авторизация** – процесс для уже получивших доступ к системе юзеров, чтобы определить их права на использование данных.

## Две основные версии SQL Server

**Express**

- наша, в которой работаем мы, это облегчённая версия SQL Server;
- предназначена для разработчиков приложений;
- поддерживает интеграцию общеязыковой среды выполнения CLR и собственный язык XML;
- SQL Server Management Express для SQL Server Express, http://msdn.microsoft.com/express.

**Standard Edition** – версия предназначена для малого и среднего бизнеса.

## Хранение объектов баз данных

**Страницы** – страница — это основная единица хранилища данных. Размер страницы 8 КБ, её заголовок 96 байтов. Страницы бывают страницы индексов и данных.

**Экстенты** – это непрерывная область памяти, которую выделяет СУБД. Размер его 64 килобайт.

**Файлы.**

**Файловые группы** – переименованный набор файлов БД, все файлы БД делятся на вторичные и первичные.

## Основные файлы БД

**Первичный файл (.mdf):** Главный файл БД. Содержит все таблицы (метаданные) и основные пользовательские данные. У базы данных всегда только один такой файл.

**Вторичные файлы (.ndf):** Вторичные файлы. Используются, чтобы размазать большие данные по разным дискам для ускорения работы. Их может быть сколько угодно.

**Файлы журнала транзакций (.ldf или .log):** Дневник всех изменений. Сюда записываются все операции до того, как они попадут в файлы данных. Нужен для отмены ошибочных действий и восстановления базы при сбоях.

## Принципы проектирования логической схемы базы данных

<img src="https://github.com/user-attachments/assets/f3913e3f-85f3-4d36-b701-64dd601c4803" alt="image" width="600"/>

**Системный админ:** БД – это набор файлов ОС, имеющих определённую структуру.

**Проектировщик:** БД – это логическая схема данных, набор структурированных данных с заданными ограничениями и связями.

**Пользователь:** БД представлена в виде подмножества таблиц или представлений, набора процедур и функций на языке T-SQL и пр.

Главная идея независимости уровней -- изменение файлов на диске не должно ломать логическую схему таблиц, а изменение таблиц не должно мешать работе пользователя. Все три уровня не зависят друг от друга. На практике идеальной свободы нет, уровни имеют лишь частичную независимость.

## Продолжение основ T-SQL

**Пакет** – группа операторов языка T-SQL, обрабатывающаяся сервером СУБД вместе.

<img src="https://github.com/user-attachments/assets/e450c46a-bd9f-4463-9663-9e910c092d3f" alt="image" width="600"/>

**DECLARE** служит для объявления переменных в формате: имя и тип.

```sql
declare @x int = 1
        @y decimal (7, 2),
```

**Область видимости переменной** – все инструкции между её объявлением и концом пакета, где она объявлена.

## Операторы присваивания

- инициализировать в `DECLARE`;
- присвоить значение `SET`;
- присвоить значение `SELECT`.

<img src="https://github.com/user-attachments/assets/893d5948-d09c-448d-afb1-dbfa6d6e700b" alt="image" width="600"/>

**CAST и CONVERT** – нужны для преобразования типов данных! (например, сделать из числа 123 текст '123').

В чём разница: `CAST` – работает почти во всех СУБД и пишется так: `CAST(<выражение> AS <тип данных> [ (длина) ])`.

`CAST` для `NULL` = `NULL`, но умеет только тупо менять тип, без настроек.

`CONVERT` – это фишка SSMS. Пишется так: `CONVERT (<тип данных> [ (длина) ] , (<выражение> [ , style ] )`.

Главный плюс (зачем он реально нужен): он незаменим при работе с датами и временем.

## Встроенные функции языка T-SQL

- `round(X, n)` – округление числа X до n знаков после запятой.
- `floor(X)` – округление вниз (ближайшее меньшее целое).
- `ceiling(X)` – округление вверх (ближайшее большее целое).
- `power(X, y)` – возведение X в степень y.

Также есть **конкатенация** (сложение строк):

```sql
print ' @y1 = ' + CAST(@y1 as varchar(20)) +
      ' @y2 = ' + CAST(@y2 as varchar(20)) +
      ' @y3 = ' + CAST(@y3 as varchar(20)) +
      ' @y4 = ' + CAST(@y4 as varchar(20)) +
      '   % = ' + CAST(@y4/@y2*100 as varchar(20))
```

## Встроенные строковые функции в T-SQL

- `substring(стр, старт, длина)` – вырезать кусок строки (подстроку).
- `ltrim(стр) / rtrim(стр)` – удалить пробелы слева / справа.
- `lower(стр) / upper(стр)` – перевести в нижний / верхний регистр.
- `replace(стр, что, на_что)` – заменить одни символы на другие.
- `space(n)` – создать строку из n пробелов.
- `replicate(стр, n)` – повторить строку n раз.
- `patindex('%шаблон%', стр)` – найти позицию первого вхождения шаблона.

## Встроенные функции даты и времени

- `DATEADD (datepart, number, date)` – добавляет или отнимает указанное количество единиц времени к дате.
- `DATEPART (datepart, date)` – вырезает из даты нужную часть datepart.
- `DATEDIFF ( datepart , startdate , enddate )` – считает разницу.

## Системные функции

- `@@ROWCOUNT` – сколько строк обработал последний запрос.
- `@@ERROR` – код ошибки последней операции.
- `@@SERVERNAME` – имя текущего сервера.
- `@@IDENTITY` – ID.
- `@@SPID` – ID текущей сессии.
- `@@VERSION` – версия, сборка и дата релиза SQL Server.
- `@@TRANCOUNT` – число открытых транзакций в сессии.
- `@@FETCH_STATUS` – статус последней строки курсора.
- `@@NESTLEVEL` – уровень вложенности.

Есть оператор **RETURN**, нужный для немедленного выхода из кода. Кроме того, есть СИ-подобные операторы как `BEGIN/END`, `IF/ELSE`, `WHILE/TRUE`, `BREAK/CONTINUE`, `TRY/CATCH`, `RAISEERROR`, `TRY/CATCH`, `WAITFOR`.

## Курсор

Курсор нужен для хранения результата запроса и для обработки строк результирующего набора запись за записью.

Самые важные команды курсора:

- `DECLARE` – объявление курсора и привязка к SELECT-запросу.
- `OPEN` – открытие курсора (заполнение его данными).
- `FETCH` – считывание текущей строки (проверка статуса через `@@FETCH_STATUS`).
- `CLOSE` – закрытие курсора (очистка данных).
- `DEALLOCATE` – полное удаление курсора из памяти.

**Хранимые процедуры** – это мини-программы в БД. Могут делать всё.

**Функции:**

- **Скалярные** — принимают параметры и возвращают одно конкретное значение (число, строку, дату).
- **Табличные** — работают как таблицы, возвращают целый набор строк.

**Представления (VIEW)** - это виртуальная таблица, содержимое которой определяется запросом. Из преимуществ:
1. Упрощают SQL-операции
2.  Они защищают данные, так как представления могут дать доступ к части таблицы, а не ко всей таблице.
3.  Представления позволяют возвращать отформатированные значения из таблиц в удобной форме

Модифицируемое представление - когда при изменении данных в самом представлении, эти данные изменятся и в таблицах, которые эти данные хранят (при использовании оператора UPDATE/INSERT/DELETE к представлению, данные обновятся и в таблицах)

Типы представлений:
1. Индексированные представления
2. Секционированные представления
3. Системные представления

Команда для **представления** - CREATE VIEW название_представления [(столбец_1, столбец_2, ....)]
AS выражение_SELECT

Команда для **изменения представления** - ALTER VIEW название_представления [(столбец_1, столбец_2, ....)]
AS выражение_SELECT

Команда для **удаления представления** - DROP VIEW OrdersProductsCustomers.

Группировка GROUP BY схлопывает исходные строки, превращая группу записей в одну строку, из-за чего теряются  детали сотрудников или товаров, а VIEW становится немодифицируемым. В отличие от неё, оконная группировка PARTITION BY сохраняет структуру таблицы без изменений, рассчитывая итоги отдельно для каждого блока данных и выводя их новой колонкой напротив каждой детальной строки, что позволяет видеть и частные данные (например, имя и зарплату), и общие показатели группы (средний балл или сумму отдела) в рамках 1 запроса.
