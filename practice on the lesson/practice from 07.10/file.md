

### Тема ПРАКТИЧЕСКОЙ РАБОТЫ ЗА 07.10 - Управление правами доступа и безопасностью в СУБД SQL Server. 

- Цель задачи: сделать и закрепить на практике способы управления доступом (создание учетных записей, привязка пользователей, распределение ролей и назначение явных разрешений) с использованием как графического интерфейса (GUI) SSMS, так и инструкций T-SQL (классического и современного синтаксиса).

**Что было сделано по ВСЕМ ЗАДАЧАМ:**
- 13: На скриншоте показано окно редактора SQL-запросов SSMS с командами создания двух типов серверных имен входа и сообщениями об ошибках компиляции в нижней панели.
С помощью инструкций CREATE LOGIN была выполнена попытка зарегистрировать пользователя SQL Server dev11 с паролем и учетную запись Windows TP\studentcoll, однако сервер вернул ошибки, так как оба имени входа уже существуют в системе.

- 14 слайд
На скриншоте представлено окно редактора T-SQL с успешным выполнением старого формата команд для управления доступом на уровне сервера.
С помощью вызова системных хранимых процедур sp_addlogin и sp_grantlogin были созданы учетные записи для нового пользователя my_user и учетной записи Windows TP\studentcoll.

- 56, 57 слайды
На скриншоте показано окно редактора T-SQL с успешным выполнением скрипта для демонстрации работы запрещающих и отменяющих разрешений в СУБД. С помощью инструкций DENY был реализован жесткий запрет на создание таблиц и любые манипуляции с объектом dbo.authors для пользователей bokov и dirina, после чего команда REVOKE продемонстрировала корректную отмену ранее назначенных запретов.

- 52, 53, 54 слайды
На скриншоте представлен комплексный T-SQL скрипт для детального разграничения прав доступа пользователя dev2 к объектам базы данных и выведенная внизу таблица результатов проверки. С помощью команд GRANT пользователю были точечно назначены различные уровни разрешений (выборка, изменение, выполнение, создание объектов в схеме dbo), а итоговый запрос к системному представлению sys.database_permissions подтвердил успешное применение всех настроек безопасности.

- 39 и 40 слайды
На скриншоте показано сравнение двух окон редактора T-SQL для демонстрации старого и нового синтаксиса управления членами ролей базы данных. Выполнено добавление пользователя dev2 в роль db_datawriter и последующее его удаление с помощью современной инструкции ALTER ROLE ... ADD/DROP MEMBER (в левом окне) и устаревших системных процедур sp_addrolemember / sp_droprolemember (в правом окне).


- 34 и 35 слайды
На скриншоте представлен скрипт T-SQL, демонстрирующий два альтернативных подхода к управлению членством в серверных ролях для пользователей dev11 и TP\studentcoll. В коде успешно отработаны старый формат с системными процедурами sp_addsrvrolemember / sp_dropsrvrolemember и современный синтаксис с инструкциями ALTER SERVER ROLE ... ADD/DROP MEMBER


- 33 слайд
 показано графическое диалоговое окно (GUI) SSMS для создания и настройки свойств роли базы данных. В данном интерфейсе продемонстрирован процесс создания новой роли, выбор принадлежащих ей схем и добавление учетных записей в список членов роли.

- 28 слайд
На скриншоте показана попытка создания пользователей базы данных и смены владельца через устаревшие системные процедуры, завершившаяся сообщениями об ошибках. Выполнение команд sp_adduser, sp_grantdbaccess и sp_changedbowner было заблокировано сервером, так как указанные учетные записи и сопоставления уже существуют или конфликтуют с текущим владельцем dbo.

- 27 слайд
На скриншоте отображен процесс создания пользователя базы данных через редактор кода и визуальное подтверждение результата в дереве Обозревателя объектов. С помощью актуальной инструкции CREATE USER был успешно зарегистрирован пользователь dev11_user для серверной учетной записи dev11.

- 25 слайд
На скриншоте представлено графическое диалоговое окно (GUI) SSMS для создания и настройки свойств пользователя базы данных. В данном интерфейсе была выполнена ручная привязка имени входа (Login) к создаваемому пользователю базы данных с указанием имени по умолчанию.

- 23 слайд
На скриншоте показано окно редактора T-SQL с успешным выполнением команды для создания новой схемы в базе данных. С помощью инструкции CREATE SCHEMA была создана схема базы данных TP\studentcoll с назначением этой же учетной записи в качестве её владельца (AUTHORIZATION).
